# Этап 3. Список пожертвований, фильтры и CSV

## Цель

Завершить третий пункт этапа 3: предоставить администратору защищенный список
пожертвований, серверные фильтры и CSV-экспорт текущей выборки. Платежный контур
и создание пожертвований в этот срез не входят.

## Принятый подход

Страница работает как серверный маршрут Next.js App Router. Состояние фильтров
хранится в query-параметрах, Prisma получает уже нормализованные условия, а CSV
использует тот же разбор фильтров. Это исключает расхождение между таблицей и
выгрузкой и не передает в браузер записи вне текущей страницы.

## Маршруты и доступ

- `/admin/donations` находится внутри существующей защищенной группы `/admin`.
- Главная страница админки получает явную ссылку на список пожертвований.
- `/admin/donations/export` возвращает CSV и самостоятельно вызывает
  `requireAdminSession()`, даже если родительский layout уже защищает страницы.
- Неавторизованный доступ к странице и экспорту перенаправляется на
  `/admin/login`.
- Вся область `/admin` получает `Cache-Control: private, no-store, max-age=0` и
  `Referrer-Policy: no-referrer`. Страница принудительно динамическая, ссылка на
  экспорт не использует prefetch.
- Сессия проверяется до разбора фильтров и обращения к репозиторию. Значения
  фильтров, параметры Prisma и содержимое CSV не записываются в журналы.

## Фильтры

Поддерживаются следующие query-параметры:

- `status`: `PENDING`, `SUCCEEDED`, `CANCELED` или отсутствие значения для всех;
- `from`: календарная дата начала периода по `createdAt`, включительно;
- `to`: календарная дата конца периода по `createdAt`, включительно;
- `q`: поиск без учета регистра по имени, email или `providerPaymentId`;
- `page`: положительный номер страницы, по умолчанию `1`, только для HTML.

Общий чистый модуль имеет два режима. HTML-разбор валидирует все пять параметров,
а экспорт полностью игнорирует `page`, включая повторяющиеся и некорректные
значения, и валидирует только `status`, `from`, `to`, `q`. Модуль формирует Prisma
`where` и канонические параметры для ссылок.

Для каждого поддерживаемого параметра допускается не более одного значения.
Значения обрезаются по краям; пустая строка считается отсутствием фильтра.
`status` принимает только указанные значения. `q` содержит не более 120 символов.
`page` соответствует `^[1-9][0-9]{0,5}$`, поэтому дроби, экспоненциальная запись,
нули и значения выше `999999` отклоняются. Применение формы фильтров не передает
`page` и тем самым возвращает пользователя на первую страницу. Некорректный
фильтр не запускает запрос: HTML показывает нейтральное сообщение, CSV отвечает
`400`.

Все календарные даты и отображение времени используют `Europe/Moscow`
(`UTC+03:00`). Даты принимаются только как реально существующие календарные даты
в строгом формате `YYYY-MM-DD`. Нижняя граница преобразуется в UTC из московского
начала `from`, верхняя — из московского начала календарного дня после `to`, с
условием `createdAt < nextDay`. Следующий день вычисляется календарно, а не
добавлением 24 часов. Период, где `from > to`, считается некорректным.

## Таблица и пагинация

Размер страницы фиксирован: `50`. Строки сортируются по `createdAt DESC`, затем
по `id DESC`. Колонки:

- дата создания;
- сумма и сохраненный код валюты;
- статус на русском языке;
- имя плательщика;
- email;
- идентификатор платежа провайдера.

Отсутствующие необязательные данные отображаются знаком `—`. На пустой выборке
показывается спокойное пустое состояние. Пагинация содержит команды «Назад» и
«Далее», сохраняет текущие фильтры и не создает ссылок за пределы диапазона.
Сумма форматируется из целого `amountKopecks` без потери копеек; валюта не
подменяется на RUB.

Общее число страниц равно `max(1, ceil(total / 50))`. Репозиторий выполняет
`count` и `findMany` в интерактивной Prisma-транзакции с уровнем
`RepeatableRead`: после `count` он ограничивает запрошенную страницу фактическим
диапазоном и только затем вычисляет безопасный `skip`. Если URL запрашивает
страницу выше последней, HTML перенаправляется на канонический URL последней
страницы. При нулевом результате канонической остается страница 1. Offset-
пагинация гарантирует стабильный порядок только пока набор данных не меняется.

Форма фильтров использует обычный `GET`: статус выбирается в `select`, период —
двумя полями `date`, поиск — текстовым полем. Отдельная команда очищает фильтры.
На мобильном экране фильтры складываются в одну колонку, а таблица получает
горизонтальную прокрутку внутри собственной области без переполнения страницы.

## CSV-экспорт

Экспорт применяет `status`, `from`, `to` и `q`, полностью игнорирует `page` и
выгружает всю отфильтрованную выборку. Репозиторий читает записи пакетами по 1000
через keyset-курсор `(createdAt, id)` в том же порядке, что таблица. Ответ
передается через `ReadableStream`, поэтому размер выборки не ограничен памятью
одной строки ответа.

Точный порядок заголовков: `ID`, `Дата создания`, `Сумма`, `Валюта`, `Статус`,
`Код статуса`, `Имя плательщика`, `Email`, `ID платежа`, `Дата оплаты`. Сумма
записывается десятичным числом с двумя знаками и точкой, временные метки — как
`YYYY-MM-DD HH:mm:ss +03:00`, отсутствующие значения — пустой строкой. Нулевая
выборка создает файл только с заголовком.

Файл кодируется в UTF-8 с BOM, использует точку с запятой, CRLF, двойные кавычки
вокруг каждого поля и удвоение внутренних кавычек. Для каждого недоверенного
текстового значения проверяется первый символ после пробельных и управляющих:
`=`, `+`, `-`, `@`, а также исходные ведущие tab/CR/LF считаются опасными. Перед
CSV-экранированием к исходной строке добавляется апостроф. Ответ содержит
`Content-Type: text/csv; charset=utf-8`, `Content-Disposition: attachment`,
`Cache-Control: private, no-store, max-age=0` и `Referrer-Policy: no-referrer`.
Имя файла использует текущую московскую дату.

## Доступ к данным

Добавляется единый экземпляр Prisma Client с development-кешированием в
  `globalThis`, чтобы hot reload не создавал лишние подключения. Репозиторий
  пожертвований предоставляет операции:

- получить согласованную страницу и общее количество через `RepeatableRead`;
- получить очередной пакет CSV после необязательного keyset-курсора.

UI и HTTP-маршрут зависят от интерфейса репозитория, а не собирают Prisma-запросы
самостоятельно. Это позволяет тестировать поведение без рабочей PostgreSQL.

## Ошибки и ограничения

- Ошибки конфигурации или базы не раскрывают строку подключения и детали Prisma.
- Страница использует локальный error boundary с понятным сообщением и повтором.
- Экспорт возвращает нейтральный `500`, если ошибка возникла до начала потока.
  Ошибка после отправки заголовков завершает поток и журналируется без значений
  фильтров, PII и деталей Prisma.
- CSV не включает `idempotenceKey`, потому что он нужен платежному контуру, а не
  операционной выгрузке.
- На этом этапе администратор только читает данные; изменение статусов вручную не
  добавляется.

## Проверки

- unit-тесты пустых/повторных параметров, невозможных дат, московских границ,
  строгого номера страницы, длины `q` и Prisma `where`;
- unit-тесты денег, времени, CSV-кавычек, CRLF, разделителей, ведущих управляющих
  символов и каждого префикса формулы;
- тест репозитория с подмененным Prisma Client: фильтры, сортировка, пагинация;
- тест страницы: пустое состояние, строки, валюта, сохранение фильтров,
  чрезмерная страница и нулевой результат;
- тест CSV route: защита сессией, заголовки, только отфильтрованные строки,
  header-only файл, пакетный поток, ответы `400`, ранний `500` и сбой потока;
- тест, что неавторизованный запрос не разбирает фильтры и не вызывает репозиторий;
- тест `no-store`, referrer policy и отключенного prefetch;
- accessibility-тест формы и таблицы;
- полный `npm test`, lint, typecheck, Prisma validate/generate и production build;
- браузерная проверка desktop/mobile, фильтров, пустого состояния и скачивания.

Страница Next.js 16 ожидает асинхронный `searchParams`; route handler читает
`request.nextUrl.searchParams`. Индекс для `(createdAt, id)` добавляется отдельной
Prisma-миграцией, а производительность поиска `contains` контролируется по мере
роста данных.

Если доступна одноразовая PostgreSQL, миграция применяется и репозиторий
проверяется интеграционно. Отсутствие такой базы фиксируется в итоговом отчете.
