## Реальная работа с PostgreSQL

- Главная: прежние загрузчики возвращали 1000 проектов, 1000 групп сумм и 1000 документов; новые — 3 + 3 + 3 строки. Число операций остаётся три, уменьшается объём чтения/передачи/обработки. Результат совпадает с первыми тремя элементами прежней выдачи.
- EXPLAIN ограниченного Project SELECT показывает Index Only Scan Backward по существующему `Project_status_publishedAt_id_idx`, LIMIT3; новый индекс не потребовался.
- Новый пользовательский обзор сохраняет пять событий. Общий helper пакетно проверяет существование объектов и дедуплицирует ID; полный журнал использует тот же механизм. В тестовой модели обзор выполняет 12 Prisma read-операций, включая один запрос существования проектов; BEGIN/COMMIT не включены.
- Sitemap получает только slug, а для документов — один ID через findFirst; форма выбора пожертвования получает только title/slug.
- Полные PostgreSQL-прогоны на итоговой схеме: content migration2, admin migration3, content repository2, admin operations6, cleanup2, платежи19 — **34 теста, все прошли**. Пропуски этих suites в обычном unit-прогоне не выдаются за DB-проверку.

## Кеш: решение

Общий межзапросный кеш в этом релизе не вводится: публичные p95 ниже выбранной цели500мс, главная и sitemap получили выигрыш от узких запросов, доказанного основания для Redis/инвалидации нет.
