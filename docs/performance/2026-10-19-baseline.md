# Исходные условия измерений — 19 октября 2026

Базовая версия: пользовательский коммит `52aac51` с обновлёнными публичными страницами, папками обращений и журналом. Оптимизации сравнивались с отдельной замороженной копией этой версии; её собственные изменения не откатывались. Обе сборки используют одну изолированную локальную БД и одинаковые фикстуры.

- macOS arm64; Node.js 25.4.0 для обеих HTTP-сборок; Next.js 16.4.2; Prisma 6.12.0; PostgreSQL 16.11.
- Отдельный PostgreSQL16 на loopback:55439, БД foundation_optimization_test. Производственная БД не использовалась.
- Синтетические фикстуры: 1000 проектов, 1000 новостей, 1000 документов, 100000 успешных пожертвований, 10 audit-событий с повторными ID и одной удалённой сущностью.
- Для каждого маршрута, варианта и concurrency запускается свежий production-процесс; 10 запросов прогрева, затем 3 серии по 100 запросов. Concurrency: 1 и 5.
- Порядок: before → after для каждого маршрута/concurrency. Другие тесты и сборки во время парных замеров не выполнялись. Соседние процессы ОС полностью не изолированы.
- p95 в сводной таблице — медиана трёх серий; это не production SLA и не прогноз при другом железе/объёме данных.
- RSS HTTP-процесса — снимок после серии; sampledPeakRss media — выборочный максимум с периодом 10мс, не гарантия пикового потребления.

Ранние последовательные замеры на долго живущем процессе дали сильный разброс из-за накопления памяти после больших коллекций; их не использовали для вывода об ускорении. Парные исходные данные сохранены в `2026-10-19-http-measurements.json`.

Воспроизведение: `scripts/performance-seed.mjs`, `vitest.performance.config.ts` и `scripts/measure-public-performance.mjs`. Для независимого маршрута задайте `PERF_ROUTES=/` (или один из разрешённых маршрутов) и запускайте свежий сервер до каждого варианта. Скрипты допускают только локальные origin/специальную тестовую БД.
