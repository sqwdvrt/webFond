# Резервное копирование и восстановление

Статус 17 ноября 2026: инструкция подготовлена. Настройки production backup,
сроки хранения и восстановление боевой копии в этой работе не проверены.

## Проверка владельцем инфраструктуры

1. В Timeweb открыть кластер PostgreSQL; подтвердить автоматическое расписание,
   последнюю успешную копию, срок хранения и доступность восстановления.
2. Отдельно проверить S3: резервная копия PostgreSQL не содержит загруженные файлы.
   Подтвердить политику сохранности объектов и способ восстановления файлов.
3. Записать ответственного, допустимую потерю данных (RPO) и допустимое время
   восстановления (RTO). Значения определяет фонд по возможностям инфраструктуры;
   эта инструкция не обещает заданный уровень доступности.

## Пробное восстановление

1. Создать изолированную БД из выбранной копии штатным механизмом Timeweb.
   Не восстанавливать поверх работающего кластера и не подключать публичное preview.
2. Ограничить доступ: копия содержит персональные данные. Использовать отдельные
   credentials и закрытую среду на территории РФ по действующей политике фонда.
3. Отключить входящие публичные запросы, исходящие платежи, email и scheduler;
   `PAYMENTS_ENABLED=false` само по себе не отключает webhook/maintenance.
   Восстановление можно проверять через psql без запуска приложения.
4. Сверить список миграций с версией приложения, структуру таблиц и количества строк;
   проверить доступность выбранных S3-объектов, не публикуя содержимое.
5. Если нужен запуск приложения, использовать только закрытый стенд без внешних
   credentials и заданий; проверить вход, чтение списков, реквизитов и документов.
6. Записать дату копии, длительность, результат, остаточные проблемы. Не включать
   в отчёт строки обращений, email, платёжные данные или URL с credentials.
7. Удаление временной копии выполнить по согласованной процедуре хранения данных.

## Аварийное восстановление

Остановить новые записи на общем входе, сохранить сведения о последних транзакциях
и определить диапазон потенциально потерянных платежей. Восстановить кластер,
подключить совместимую версию приложения, затем сверить платежи с ЮKassa по штатному
механизму. Не назначать SUCCEEDED вручную по сумме/скриншоту. Открывать приём новых
обращений и платежей только после проверки миграций, согласий и сверки состояния.
